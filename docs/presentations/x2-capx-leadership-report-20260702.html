X2 接入 CaP-X / BEHAVIOR 工作汇报 · 2026-07-02

从 5090 仿真环境适配到 X2 视觉抓取闭环

这项工作的核心不是单个抓取视频，而是把自研 X2 机器人接入 BEHAVIOR/CaP-X 的任务体系，并形成可继续迁移到实物的视觉、动作和调试闭环。

Isaac Sim 5.1 / BEHAVIOR X2 + 85 型欠驱动夹爪 CaP-X-b1k RGB-D visual pick-place ASPIRE-lite trace/candidate loop

当前状态

平台：5090 上的 BEHAVIOR / Isaac Sim 5.1 可用，自定义机器人导入链路已修复。

机器人：X2 已注册带爪版本，具备桌面 pick-place 基础能力。

CaP-X：LLM 通过任务级 primitive 调用 X2，不直接处理 env setup。

验证：RGB-D / ASPIRE-lite validation 3/3 通过。

为什么这件事不是直接改 CaP-X 就能完成

阶段 1

5090 环境约束

CaP-X 自带的 third_party BEHAVIOR 与当前 5090 显卡环境不匹配。解决路线改为独立安装官网 BEHAVIOR，并适配 Isaac Sim 5.1。

阶段 2

修复 BEHAVIOR 自定义机器人导入链路

独立 BEHAVIOR 配通后，发现该版本自定义机器人导入 pipeline 存在问题。已打补丁修复，并对官方 main 与修改导入后的 main 做烟测。

本地补丁提交：0f6705681 Fix custom robot import for Isaac Sim 5.1

阶段 3

补齐 X2 的任务执行条件

X2 原始模型不能自然完成抓取任务。参考官方 Franka + 85 型欠驱动夹爪示例，写了 X2 安装夹爪脚本，并注册带爪/不带爪版本。

阶段 4

形成 CaP-X-b1k 工程分支

在适配后的 BEHAVIOR 基础上，修改 CaP-X，使任务 setup 留在 config/env 层，LLM 代码只调用高层 X2 primitive。

当前仓库：https://github.com/programessi/CaP-X-b1k.git

阶段 5

并行沉淀实物路线

吸收 CaP-X 主线思路，配套形成 x2-agent-lab，用于后续 ROS/实物部署。仿真任务和实物部署分开推进，避免相互污染。

已经能展示的视频证据

为什么三个视频画面相似

三个视频都是同一个桌面 pick-place 场景，所以画面上都像“机械臂抓方块”。它们真正展示的是不同层级的工程闭环。

  • 第一个看 CaP-X 任务注入是否成立：LLM/任务代码只调用高层 primitive。
  • 第二个看视觉链路是否成立：目标选择、分割、RGB-D 障碍物、抓取位姿接入动作。
  • 第三个看 ASPIRE-lite 是否有用：通过 trace/candidate 发现并修复 place 阶段不稳定。

现场播放建议

不要连续完整播放三个视频。建议每个视频只播放 10-20 秒，同时讲清楚“这一段证明的是哪一层能力”。

主视频用 RGB-D non-oracle；ASPIRE-lite 视频作为“修复后 validation”证据。

现场建议：先播放第二个 RGB-D non-oracle 视频，再播放第三个 validation 视频。第一个视频用来说明 CaP-X primitive 接入已经成立。

ASPIRE 之后，我加了什么

Trace-first 调试

每次运行保存生成代码、primitive 调用、视觉中间结果、抓取候选、运动 waypoint、误差指标、视频和 failure report。

失败分类

把失败归因到感知、分割、深度点云、抓取位姿不可达、接近位姿没到、夹取失败、放置误差等类别。

候选策略搜索

不是随意改底层代码，而是在高层 primitive 参数上搜索：候选 grasp、TCP offset、reobserve、place descent、place orientation。

已验证的修复

发现 place-pre 已到位后重复 IK move 会导致末端跳走；修复为到位检测 + 使用 post-lift TCP orientation，3 个 validation seed 全部通过。

目前工作的价值

平台价值

把 5090 + Isaac Sim 5.1 + BEHAVIOR 的环境坑补上，并使自定义机器人导入可用。

机器人价值

X2 从模型注册推进到带夹爪、可执行桌面操作任务，并形成仿真/实物两条路线。

CaP-X 价值

LLM 只看高层 primitive，环境和任务由 config 层承载，符合 CaP-X 的代码注入范式。

算法价值

视觉抓取、RGB-D 障碍物估计、无提前碰撞接近、关节 IK 执行已经串成一条闭环。

调试价值

ASPIRE-lite 让失败可追踪、可分类、可对比，而不是只依赖人工看视频。

后续价值

为 2real 做准备：减少 sim truth 依赖，保留 ROS/实物部署工程线。
