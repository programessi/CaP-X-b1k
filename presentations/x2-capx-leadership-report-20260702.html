技术路线

阶段 1

5090 环境约束

CaP-X 自带的 third_party BEHAVIOR 与当前 5090 显卡环境不匹配。解决路线改为独立安装官网 BEHAVIOR，并适配 Isaac Sim 5.1。

阶段 2

修复 BEHAVIOR 自定义机器人导入链路

独立 BEHAVIOR 配通后，发现该版本自定义机器人导入 pipeline 存在问题。已打补丁修复，并对官方 main 与修改导入后的 main 做烟测。

本地补丁提交：0f6705681 Fix custom robot import for Isaac Sim 5.1

阶段 3

补齐 X2 的任务执行条件

X2 原始模型不能自然完成抓取任务。参考官方 Franka + 85 型欠驱动夹爪示例，写了 X2 安装夹爪脚本，并注册带爪/不带爪版本。

阶段 4

形成 CaP-X-b1k 工程分支

在适配后的 BEHAVIOR 基础上，修改 CaP-X，使任务 setup 留在 config/env 层，LLM 代码只调用高层 X2 primitive。

当前仓库：https://github.com/programessi/CaP-X-b1k.git

阶段 5

并行沉淀实物路线

吸收 CaP-X 主线思路，配套形成 x2-agent-lab，用于后续 ROS/实物部署。仿真任务和实物部署分开推进，避免相互污染。

当前 CaP-X 任务闭环

任务代码不再负责创建场景、重置仿真、手动搭机器人或直接调 IK/相机服务。CaP-X 注入给 LLM 的是少量任务级函数。

阶段验证

验证组织

本页将验证材料按工程能力拆分，分别对应机器人接入、视觉链路和 ASPIRE-lite 调试验证。视频作为运行记录，视觉中间结果和指标作为主要解释依据。

  • 实验 1 展示 X2 导入夹爪后，机械臂和夹爪低级动作可以执行。
  • 实验 2 展示视觉 primitive 的中间产物，不只展示最终抓取视频。
  • 实验 3 展示不同 seed 下目标/干扰物位置变化，以及修复策略的验证指标。

验证范围

验证覆盖模型导入、夹爪执行、视觉感知、动作执行和失败诊断。实验三的三个 seed 使用不同的目标方块位置和干扰物位置。

实验 1 · X2 夹爪与低级动作验证

导入夹爪后，X2 具备执行任务的基本动作条件

该实验验证 X2 带 85 型欠驱动夹爪版本可以在 BEHAVIOR/Isaac Sim 中加载、运动、保持末端姿态，并执行夹爪闭合/打开。

  • 验证自定义机器人导入和夹爪装配链路可用。
  • 验证动作原语调试具备硬件模型基础。
  • 为后续视觉抓取任务提供可执行末端执行器。

实验 2 · RGB-D 视觉 primitive 链路

从视觉输入到抓取位姿

该实验重点展示视觉链路的中间结果：先由相机 RGB-D 输入定位目标，再通过检测和分割得到目标区域，随后利用深度点云估计物体/桌面障碍物，并把 Contact-GraspNet 产生的 TCP 抓取位姿接入动作原语。

  • OWL-ViT / SAM2 找到目标并分割。
  • RGB-D 点云估计目标和桌面障碍物。
  • Contact-GraspNet 生成抓取 TCP 位姿并接入动作链路。

实验 3 · ASPIRE-lite 修复策略验证

不同 seed 下的修复策略验证

该实验来自 `place_skip_redundant_prepose_3seed_20260701`。三个 validation seed 的目标方块位置和干扰物位置均有扰动，验证的是修复后的动作策略在小范围布局变化下是否仍能完成任务。

ASPIRE-lite 扩展

Trace-first 调试

每次运行保存生成代码、primitive 调用、视觉中间结果、抓取候选、运动 waypoint、误差指标、视频和 failure report。

失败分类

把失败归因到感知、分割、深度点云、抓取位姿不可达、接近位姿没到、夹取失败、放置误差等类别。

候选策略搜索

候选策略搜索约束在高层 primitive 参数内，包括 grasp candidate、TCP offset、reobserve、place descent 和 place orientation。

已验证的修复

发现 place-pre 已到位后重复 IK move 会导致末端跳走；修复为到位检测 + 使用 post-lift TCP orientation，3 个 validation seed 全部通过。

目前工作的价值

平台价值

把 5090 + Isaac Sim 5.1 + BEHAVIOR 的环境坑补上，并使自定义机器人导入可用。

机器人价值

X2 从模型注册推进到带夹爪、可执行桌面操作任务，并形成仿真/实物两条路线。

CaP-X 价值

LLM 只看高层 primitive，环境和任务由 config 层承载，符合 CaP-X 的代码注入范式。

算法价值

视觉抓取、RGB-D 障碍物估计、无提前碰撞接近、关节 IK 执行已经串成一条闭环。

调试价值

ASPIRE-lite 提供失败追踪、失败分类和策略对比能力，降低只依赖人工查看视频的调试成本。

后续价值

为 2real 做准备：减少 sim truth 依赖，保留 ROS/实物部署工程线。
